The gap

Most tools check one table at a time.

The expensive failures live between systems: a value that changed on the way to the warehouse, a key that lost its source, a row that vanished in a pipeline hop. trueset validates within a dataset and across datasets — on whatever engine holds them. Same check, same result, whether it runs in memory or as SQL pushed into your database.

Checks as config

Readable checks. Real enforcement.

Declare what should be true in YAML or Python. Run it in CI, in your pipeline, or against the warehouse — the CLI exits non-zero when data is bad, so it gates a pipeline out of the box.

reconcile.yml
suite: warehouse_vs_source
checks:
  - type: row_count_parity      # counts agree within tolerance
    reference: source
  - type: referential_integrity  # every key traces back to the source
    column: order_id
    reference: source
    ref_column: id
  - type: value_parity           # join on key, compare the values
    key: order_id
    columns: [amount, status]
    reference: source

$ trueset reconcile --data warehouse.csv --checks reconcile.yml --ref source=source.csv

What you get

Four things, done plainly.

Portable

One backend protocol. Write a check once; run it on pandas, DuckDB, Postgres, or Snowflake with no rewrites. Verified identical across engines by the test suite.

Reconciliation

Row-count parity, referential integrity, and value parity across two systems — the cross-system checks single-source tools can’t express.

Shift-left

Validate in flight, before data lands. Block a bad batch, or quarantine the failing rows and keep the clean ones moving downstream.

Auditable

Deterministic results as JSON. Tag checks with owner, sensitivity, and regulation for policy reports you can hand an auditor.
